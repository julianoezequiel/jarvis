# O que é o  AIOS CORE 

O AIOS CORE  (AI -Orchestrated System for Full Stack Development ) é um framework da Synkra AI que organiza uma equipe de 11 agentes especializados para construir produtos digitais completos — do briefing ao deploy — através de conversas .

A inovação central do sistema é o chamado  Planejamento Agêntico : ao invés de pedir para uma IA genérica "construir um app ", você passa por uma sequência estruturada onde cada agente especializado contribui com sua expertise , e o resultado de cada etapa alimenta a próxima . Isso elimina o principal problema do desenvolvimento assistido por IA : perda de contexto e inconsistência de planejamento .

"Neste minicurso , você vai construir o FinFlow  — um app de gerenciamento financeiro pessoal para autônomos brasileiros — do zero ao deploy ,

conduzindo cada etapa com uma conversa simples para o agente certo ."

O @architect recebe o PRD e backlog , e define como o app funciona por dentro —

> ◈A I O S C O R E ·W E B U I ·/ a r c h i t e c t ·S E S S Ã O I N I C I A D A
> VOCÊ

Architect , recebeu o PRD e o backlog do FinFlow . Preciso das decisões de arquitetura : qual stack usar , como os dados são estruturados , ecomo garantir que funcione offline no celular . Quero que funcione de graça para os primeiros 10.000 usuários .

> @ARCHITECT

Analisando requisitos . Restrições principais identificadas : custo zero até 10 kusuários , suporte offline , web + mobile , stack que o @dev possa executar sem ambiguidade . Decisões :

Stack recomendada : Next .js (framework ) + Supabase (banco + auth + tempo real ) + Vercel (hosting ) + PWA (mobile sem App Store ). 

Justificativa custo -zero : Vercel free tier suporta 100 k requests /mês .

Supabase free suporta 50 k MAUs . Juntos cobrem os primeiros 10 k usuários com folga .

Estratégia offline : dados salvos localmente via localStorage /IndexedDB como fonte primária . Supabase como camada de sincronização . O app funciona mesmo sem internet — sincroniza quando a conexão volta .

Modelo de dados simplificado :

users : id , email , nome , plano (free /premium )▸

transactions : id , user _id , valor , tipo (receita /despesa ), categoria , tipo _conta 

(pessoal /profissional ), data , descricao

Três decisões irreversíveis que você precisa confirmar antes de escrever uma linha de código :

1. Moeda única (R$ ) ou multi -moeda ? Implementar multi -moeda depois é uma reescrita de toda a camada de cálculo . Para v1.0 foco no Brasil , recomendo moeda única — confirmar ?
